# Creating forms in Alibi

Every form uses the wrappers in `frontend/src/components/form/` and a zod schema. This keeps validation, error display and styling identical across the app. Never use raw `<input>`, `<Input>`, `<Select>` or other shadcn controls directly inside a form, and never hand-write validation or error text in JSX.

## Available components

Import from `@/components/form`. All take `control` and `name` (typed to your schema), plus optional `label` and `description`. Each renders its shadcn `FieldError` automatically.

| Component | Use for | Extra props |
|---|---|---|
| `FormInput` | text, email, password, number, OTP | any `<Input>` prop (`type`, `placeholder`, `autoComplete`) |
| `FormTextarea` | multi-line text | any `<Textarea>` prop |
| `FormSelect` | one choice from a list | `options: {value,label}[]`, `placeholder`, `disabled` |
| `FormRadioGroup` | few visible choices (avatars, suspect pick) | `options` |
| `FormCheckbox` | boolean consent / agree | `label` required |
| `FormSwitch` | boolean setting | `label` required |

If the input you need has no wrapper (date picker, OTP slots, file upload), add a new `Form*` component in `src/components/form/` that follows `FormFieldShell` and `FormInput`, export it from `index.ts`, then use it. Install any missing shadcn primitive first (`npx shadcn@latest add <name> -y`). Do not edit files in `components/ui/`.

## Recipe

1. Define the zod schema with the error messages users should see. Put reusable schemas in the same file as the form, or in `src/utils/validation.ts` if shared.
2. Infer the type, create the form with the resolver and full `defaultValues` (strings `''`, booleans `false`, so inputs stay controlled).
3. Render with `FieldGroup` and the `Form*` components, and submit through `handleSubmit`.
4. Send data through the mutation hook generated by `createApi` in `src/api/` (e.g. `useSignupMutation()`). Never call `fetch` or import React Query in the component.
5. Show server errors with `setError` for field-level problems or a `toast.error(...)` for general ones.

```tsx
import { useForm } from 'react-hook-form'
import { zodResolver } from '@hookform/resolvers/zod'
import { z } from 'zod'
import { toast } from 'sonner'
import { Button } from '@/components/ui/button'
import { FieldGroup } from '@/components/ui/field'
import { FormInput, FormCheckbox } from '@/components/form'
import { useSignupMutation } from '@/api/auth'

const schema = z.object({
  email: z.email('Enter a valid email'),
  password: z.string().min(8, 'Password must be at least 8 characters'),
  agree: z.boolean().refine((v) => v, 'You must accept the rules'),
})
type Values = z.infer<typeof schema>

export function SignupForm() {
  const { control, handleSubmit, setError } = useForm<Values>({
    resolver: zodResolver(schema),
    defaultValues: { email: '', password: '', agree: false },
  })
  const mutation = useSignupMutation({ onError: (e) => toast.error(e.message) })

  return (
    <form onSubmit={handleSubmit((v) => mutation.mutate(v))} noValidate>
      <FieldGroup>
        <FormInput control={control} name="email" label="Email" type="email" autoComplete="email" />
        <FormInput control={control} name="password" label="Password" type="password" autoComplete="new-password" />
        <FormCheckbox control={control} name="agree" label="I accept the rules" />
        <Button type="submit" disabled={mutation.isPending}>Sign up</Button>
      </FieldGroup>
    </form>
  )
}
```

## Rules and why

- **Zod v4 syntax:** use `z.email()`, not `z.string().email()`. Optional text fields use `z.string()` with `''` default, not `undefined`, to avoid uncontrolled-input warnings.
- **Messages live in the schema,** so the same wording shows everywhere and nothing in JSX duplicates validation.
- **Disable submit while pending** (`mutation.isPending`) to prevent double submits, which matters for anything that spends tokens.
- **Add `noValidate`** to the `<form>` so zod, not the browser, shows errors in the themed style.
- **Forms inside dialogs or sheets** work the same; put the `<form>` inside the content.
- **Styling** (sharp corners, gold focus glow, red error glow) comes from the theme in `src/index.css` automatically. Do not add custom error styles.

Finish with `cd frontend && npm run build && npm run lint`.
